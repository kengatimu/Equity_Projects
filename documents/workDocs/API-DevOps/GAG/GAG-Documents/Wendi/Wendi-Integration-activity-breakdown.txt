WENDI INTEGRATION – Activity Breakdown
Integration Type: B2C Transactions + Status Check + Reconciliation Service

1. B2C Transaction Flow

A. API Layer (Inbound from Channel)
	- B2C Controller development (REST endpoint)
 	- Request DTO definition and mapping
	- Global exception handling (ControllerAdvice)
	- Request logging configuration
	- Thread management configuration (Async / Executor tuning)

B. Validation Layer
	- Field-level request validation
	- Business rule validation (amount, limits, mandatory fields)
	- Duplicate transaction validation
	- Payload signature validation (digital signature verification)
	- Replay protection validation

C. Core Transaction Processing
	- Finacle debit/credit service integration (ISO 8583 call)
	- Finacle response validation (Field 39, etc.)
	- Database persistence logic (transaction master updates)

D. Outbound Call to Wendi Technical Service
	- HTTP client configuration (timeouts configurations)
	- Payload construction for Wendi technical service
	- HTTP invocation to Wendi Technical Service
	- Response timeout handling

E. Wendi Response Handling
	- Technical service response validation
	- Response code mapping (Channel response mapping)
	- Transaction status update in DB
	- Failure handling logic (trigger reversal if required)

F. Channel Callback Handling
	- Channel callback service implementation
	- Asynchronous callback processing
	- Final transaction status update
	- Logging and audit trail update

G. Infrastructure & Configuration
	- Environment configuration (SIT/UAT/PROD)
	- YAML configuration setup
	- Keystore & truststore configuration
	- Database connection setup
	- Repository layer implementation (JPA / DAO)
	- Logging configuration
	
----------

2. Transaction Status Check Flow

A. API Layer
	- Status Check Controller development
	- Request validation
	- Exception handling integration

B. Database Lookup
	- Repository implementation for transaction retrieval
	- Service layer for fetching transaction status
	- Status normalization logic (Internal to Channel response)

C. External Status Check (while calling wendi technical service)
	- HTTP call to Wendi Technical Service for status verification
	- Response validation
	- Response processing and DB update

D. Response Handling
	- Status mapping response (Channel response format)
	- Channel response service implementation
	- Audit logging
	
----------

3. Reconciliation Service

A. Timeout Detection
	- Identify transactions in PENDING state beyond threshold
	- Scheduled job / polling mechanism

B. Status Verification
	- Invoke Wendi Status Check API for timed-out transactions
	- Validate response
	- Update transaction status in DB

C. Reversal Logic
	- Trigger Finacle reversal for failed/unknown transactions
	- Update reversal status in DB
	- Log reconciliation actions

D. Reporting
	- Generate reconciliation logs
	- Maintain audit trail
	- Exception reporting for unresolved transactions
